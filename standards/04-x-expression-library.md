# 04 — X Expression Library
**Status:** DRAFT 0.2.0 · **Conceptual categories, not a limit on number of animations**

## Source and principle
The X originates in the chosen BYX display typeface. It is not a standalone master symbol. Variable X and eXperience X name **ways of thinking**, not precisely two assets or fixed SVG marks.

Each new expression should document:
- Name / semantic theme.
- Source typeface and glyph.
- Input dimensions or time model.
- Transformation rule / parameter range.
- Responsiveness and reduced-motion state.
- Appropriate applications and misuse to avoid.
- Stable still frame export for print.

## Hybrid expressions
- H-01 / Response Trace: input-driven X leaves a faint history.
- H-02 / Project Frame: project photography enters a cropped type-X aperture.
- H-03 / Field Archive: a matrix of X glyphs gradually resolves into a single statement.

## Editorial rhythm
- Use expressions actively on **ABOUT / METHOD / identity presentations**.
- Project photographs and architectural work receive priority on regular WORKS pages.
- Never require motion to understand the text.
- Animations may loop, but afford users a still or pause state. Respect reduced motion.
- For formal drawing/title-block/legal outputs, use ordinary static typography and avoid abstract artwork behind information.

## Workshopping protocol
1. Prototype on white in black.
2. Check legibility as X and conceptual relationship.
3. Review mobile, desktop and monochrome print freeze frame.
4. Add candidate to expression library with snapshot or visual spec.
5. Record two-architect approval or rejection in CHANGELOG.
