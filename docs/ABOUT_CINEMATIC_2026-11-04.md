# ABOUT · 스크롤 소개와 문의 접수

2026-11-04. 사용자가 요청한 후속 작업의 현재 기준입니다. 기존 소개 문구의 핵심인 Variable X × eXperience를 유지하며, 선택 버튼 대신 스크롤로 읽는 이야기로 바꿨습니다.

## 화면과 움직임

- 첫 화면은 검은색입니다. `POSSIBILITIES. BY X.`의 영문자들이 잠시 다른 글자로 바뀐 뒤 원래 문장에 도달합니다. 스크린리더에는 처음부터 최종 제목을 제공합니다.
- 제목은 약 155svh, X 장면은 약 230svh의 여유 구간 안에서 `position:sticky`로 잠시 고정됩니다. 휠/터치를 가로채지 않으며 사용자가 스크롤한 만큼 장면이 진행되고 다음 구간으로 넘어갑니다.
- X는 화면 가장자리와 바깥에 흩어져 시작하고 스크롤에 따라 중앙으로 날아와 입체를 이룹니다. 형성 뒤의 회전/네 가지 형상 전환과 선택적인 포인터/키보드 반응은 유지합니다.
- 업무 관점 3개·설계 과정 4개·데이터 설명 4개를 본문에서 읽습니다. 별도의 선택 버튼은 없습니다. 과정 그림과 데이터 강조는 읽는 위치에 맞춰 갱신합니다.
- BYX 함수 상자로 문서/연산/맥락/협업을 나타내는 기하학적 심볼이 들어가 입체/평면/공간 심볼로 나옵니다. 실제 연산 결과를 표시하는 기능이 아니라 역량을 설명하는 그래픽입니다.
- Studio/Records는 공개에서 제거했습니다. 기존 `settings.about.lede/studio/facts/records`를 삭제하지 않고 관리자에 보관합니다.
- 스크롤바는 숨기고 네이티브 스크롤을 유지합니다. FEED의 링크 카드 이미지는 WORKS와 동일한 확대 1.035배, transform 0.7초/필터 0.5초 전환을 사용하며 키보드 포커스에도 반응합니다.

모션 감소에서는 제목이 즉시 완성되고 점군은 형성된 정적 상태, 함수는 정적 입출력 도식, People은 자동 이동 없는 가로 목록입니다. 고정 구간의 추가 길이도 줄입니다. 화면 밖·숨은 탭·모달에서는 관련 자동 프레임을 정지하고 라우트 이탈 시 관찰자/이벤트/프레임을 정리합니다.

## People

“최고의 전문가들이 함께합니다.”라는 소개와 프로필 카드를 제공합니다. 기본 문구는 ABOUT 편집의 People 제목/소개에서 변경할 수 있습니다. 카드들은 약 18px/s로 좌→우 이동하고 같은 순서가 끊김 없이 반복됩니다.

호버·키보드 포커스·모달 동안 멈추며 별도의 멈추기/재개 버튼도 있습니다. 복사된 카드는 스크린리더/Tab 순서에서 제외하고 원래 카드 하나씩만 탐색합니다. 1명은 정적인 카드, 0명은 People 섹션 생략으로 처리합니다.

직원을 선택하면 사진·이름·직책·이력·소개 모달이 열립니다. 닫기/Esc/바깥 클릭, Tab 이동과 원래 카드 포커스 복귀를 지원합니다. 모달 중 본문 스크롤을 막고 닫거나 페이지를 이동하면 복구합니다.

CMS의 기존 `이름 | 직책 | 이력 | 사진주소` 형식은 유지하고 선택적인 5번째 `소개`를 추가했습니다. 사람별 사진 칸 아래의 소개 입력으로 편집할 수 있습니다. 줄바꿈은 저장 시 `\n`으로 표현합니다. 사진 교체/삭제가 소개를 잘라내지 않도록 수정했으며 기존 4칸 데이터는 그대로 작동합니다. 제공되지 않은 이력/자격/인물 소개를 새로 만들지 않았습니다.

## 문의하기

ABOUT 마지막 `LET'S DO IT!`의 프로젝트 문의하기 버튼은 모달을 엽니다. 제목(3~160자), 이메일, 연락처(선택), 설명(10~8000자), 답변을 위한 수집/이용 동의를 받습니다. 접수 중과 접수 후 중복 제출을 막고, 실패 시 입력을 보존합니다. 데모는 메모리에만 저장하고 실제 전송하지 않았음을 표시합니다.

문의는 **사이트 관리자 문의함**에 저장합니다. 현재 별도 메일 발송 서비스가 없어 이메일 자동 알림은 추가하지 않았습니다. 관리자 로그인 → **문의함**에서 최근 최대 100개를 읽고 새 문의/확인/완료 상태를 바꿉니다. 연락처/본문은 공개 API나 일반 방문자에게 노출하지 않습니다.

### 서버와 운영 적용

- [CONTACT_REQUESTS.sql](CONTACT_REQUESTS.sql): 새 `contact_requests` 테이블, 필드 제약, 조회/한도용 인덱스, 기존 관리자 UUID만 SELECT·상태 UPDATE 허용하는 RLS. 익명/일반 사용자의 직접 INSERT/SELECT와 공개 RPC 실행은 차단합니다.
- `submit_contact_request`는 SECURITY INVOKER이며 service_role만 실행합니다. 15분당 클라이언트 5개, 이메일당 1시간 3개, 전체 1일 100개의 DB 한도를 원자적으로 검사합니다.
- [contact-inquiry Edge Function](../supabase/functions/contact-inquiry/index.ts): 운영 배포 완료. 공개 접수 POST/OPTIONS, 허용 Origin·36KB 제한·입력 검증·동의·허니팟을 확인하고 서버 전용 RPC를 호출합니다. 클라이언트 주소는 서버 키로 HMAC 처리하며 원문 주소는 저장하지 않습니다.
- `verify_jwt=false`는 비로그인 접수를 위한 설정입니다. 비밀/서비스 키는 Supabase가 주입한 서버 환경에서만 읽으며 브라우저/새 문서에 복사하지 않습니다. 새 테이블/함수/RPC는 기존 표·데이터·Auth·Storage를 수정하지 않습니다.
- 프런트는 `index.html` 하나입니다. 실제 접수에 필요한 서버 코드만 새 Supabase Edge Function에 두며 클라이언트 라이브러리·빌드 단계는 추가하지 않았습니다. `supabase/`는 `.vercelignore`에서 제외하고 별도로 Edge Function에 배포합니다.

공식 참고: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Edge 환경 변수](https://supabase.com/docs/guides/functions/secrets). 현재 허용 출처는 Vercel 운영 주소와 같은 팀의 이 사이트 미리보기 주소입니다. 추가 도메인을 사용하려면 서버 허용 출처도 갱신합니다.
