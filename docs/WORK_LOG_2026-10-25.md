# BYX 작업 기록 — 2026-10-25

## 작업 결과

Claude로 개발하던 ARCHITECTS BY X(BYX) 공식 웹사이트를 분석하고, Codex에서 새로운 브랜드 아이덴티티를 구현하기 위한 개발 기준과 단계별 계획을 작성했습니다. 새 디자인의 화면 구현은 아직 시작하지 않았습니다.

현재 브랜치: `design/byx-brand-identity`.

## 1. 오늘 수행한 작업

### 저장소 분석

- `CLAUDE.md`, `PROJECT.md`, `CHANGELOG.md`, `index.html`, `vercel.json`, 배포 가이드를 읽고 기존 구조와 의사결정을 확인했습니다.
- 빌드 없는 단일 HTML/CSS/JavaScript 구조, 해시 라우터, Supabase CMS·Auth·Storage, Vercel 관리자 경로 rewrite를 확인했습니다.

- 슬롯머신 로고, 결정론적 SVG 생성 아트, 블로그 편집·갤러리, 이미지 축소, 데모 모드, 예전 DB 열과의 호환 처리를 보존 대상으로 정리했습니다.
- 현재 서체 Anton/SUIT Variable, 흑백 토큰, 1px 선, 유동형 여백·타이포그래피를 확인했습니다.
- 기존 문서의 줄 수·파일 크기·외부 로드 설명 중 일부가 현재 소스와 다름을 기록했습니다. 기존 문서는 수정하지 않았습니다.

## 2. 정리한 브랜드 방향

### 확정된 방향과 보존 조건

- X를 핵심 그래픽 시스템의 공통 구조로 사용합니다.
- **Variable X**: X 형태·두께·비율이 변하는 그래픽을 탐색합니다.
- **eXperience X**: X를 이미지 프레임과 인터랙션에 활용합니다.
- 본문 서체 방향은 **Wanted Sans**입니다. 실제 사이트에는 아직 적용하지 않았습니다.
- 영문 디스플레이는 Gasoek One과 유사한 정방형·두꺼운 기하학적 인상을 탐색합니다. **최종 서체는 미확정**이며 Gasoek One 채택을 확정하지 않았습니다.
- Athletics의 XR 브랜드 아이덴티티를 참고하되 직접 복제하지 않습니다.
- 별도 결정 전까지 흑백 기반 체계와 기존 블로그 본문 색상 예외를 유지합니다.
- **슬롯머신 로고는 중요한 정체성이므로 보존이 기본**입니다. 새 X 시스템을 이유로 교체·삭제하지 않습니다.
- 단일 HTML, Supabase CMS, 기존 기능, 환경설정, Vercel 배포 구조를 유지합니다. 프레임워크·빌드 도구·런타임 의존성을 추가하지 않습니다.

### 미결사항

- X 기본 윤곽·각도·끝단·교차부와 변형 범위.
- X를 적용할 화면·밀도·프레임 방식과 사진 정보 보존 기준.
- 인터랙션 트리거·지속시간·반복 여부, 모션 감소 환경의 정적 표현.
- 최종 영문 디스플레이 서체와 Wanted Sans의 버전·굵기·파일·폴백.
- 슬롯머신과 새 X 그래픽의 구체적인 배치·모션 관계.
- 파비콘·커서·공유 이미지로의 확장 범위.

## 3. 브라우저 미리보기

- 기존 실행 코드를 수정하지 않고 임시 Node 정적 서버를 실행했습니다. 서버 코드는 파일로 추가하지 않았고 패키지도 설치하지 않았습니다.
- Chrome에서 `http://127.0.0.1:8731/`을 열어 로딩 완료와 현재 WORKS 화면을 확인했습니다.
- 화면에서 슬롯 로고의 `BLOCK BY X` 정지 상태, 메뉴, GRID/INDEX 버튼과 COREARC·MOBILE RACK APT·DREAM CELLS 세 프로젝트 카드가 표시되는 것을 확인했습니다.
- 이는 현재 화면 확인이며, 새 브랜드 디자인 적용 결과가 아닙니다. 전체 기능·슬롯 반복 동작·정렬·관리자 저장을 검증한 것은 아닙니다.
- 미리보기는 기존 Supabase 설정으로 데이터를 읽었습니다. 관리자 로그인·저장·업로드·삭제 등 쓰기 조작은 하지 않았습니다.
- 마무리하면서 해당 임시 서버를 종료했습니다. 브라우저 탭이 남아 있어도 새로고침하면 서버 재실행 전에는 접속할 수 없습니다.

### 다음에 화면을 확인하는 방법

현재 구조에서는 `index.html`을 브라우저로 열거나 로컬 정적 서버로 미리볼 수 있습니다. 이번에 추가한 문서는 실행 화면을 바꾸지 않으므로 기존과 같은 디자인이 보입니다.

후속 디자인 작업은 이 브랜치에서 진행하고 로컬 미리보기와 화면 비교로 확인할 수 있습니다. 로컬 코드 변경은 배포 전까지 운영 사이트에 반영되지 않습니다. 다만 로컬에서도 기존 Supabase에 연결하면 CMS 쓰기는 운영 데이터에 영향을 줄 수 있으므로, 디자인 검증에는 데모 사본 또는 허용된 시험 환경을 사용합니다.

## 4. 실제 검증과 미검증 항목

### 수행한 확인

- 새 문서 세 개의 로컬 파일 링크를 검사했습니다.
- 작업 전후 SHA-256 비교로 `index.html`, `vercel.json`, `CLAUDE.md`, `PROJECT.md`, `CHANGELOG.md`가 동일함을 확인했습니다.
- 추적 파일 diff가 없음을 확인했습니다.
- 기존 미추적 `.claude/`를 보존했습니다.
- 브라우저에서 현재 WORKS 화면의 로딩 완료와 표시 상태를 확인했습니다.

### 수행하지 않은 확인

- 전체 라우트, 모바일·키보드·스크린리더, 모션 감소, 콘솔 오류 전수 검사.
- 실제 ADMIN 로그인·저장·업로드·삭제, 비밀글의 서버 접근 제어.
- 운영 Supabase의 스키마·RLS·Storage 정책 및 가입 설정.
- Vercel 대시보드의 운영 브랜치·도메인·환경변수·배포 설정.
- 새 폰트·X 프레임·Variable X 인터랙션의 구현과 성능 비교.

기존 `CHANGELOG.md`에 적힌 과거 테스트 결과는 오늘 재실행한 결과가 아닙니다. 구현 계획의 “브라우저 검증 미수행” 표기는 문서 작성 완료 시점의 기록이며, 이후 현재 홈 화면만 제한적으로 열어본 사실을 이 로그에 추가합니다.

## 5. 별도 후속 확인이 필요한 운영 항목

- 비밀글은 화면에서 숨기지만 배포 가이드의 SQL에는 모든 `posts` 조회를 허용하는 정책이 있습니다. 운영 정책이 같다면 API를 통한 조회 가능성이 있으므로 실제 RLS를 확인해야 합니다. 이번에 정책을 변경하거나 비밀글을 조회하지 않았습니다.
- Storage Public 버킷 생성과 업로드 권한은 별개입니다. 가이드에 쓰기 정책 설명이 부족하므로 운영 정책과 업로드 동작을 확인해야 합니다.
- 기존 기록의 추가 열 적용·실제 관리자 저장·실제 콘텐츠 입력 미완료 항목은 현재 운영 상태와 대조해야 합니다.
- 위 확인을 브랜드 변경과 묶어 SQL·권한·설정을 임의 변경하지 않습니다.
