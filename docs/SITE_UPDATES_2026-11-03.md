## 현재 결과 확인 방법

가장 간단한 방법은 [current.html](../prototypes/visual-foundation/current.html)을 브라우저로 여는 것입니다. 관리자 변경은 메모리에만 저장되며 새로고침하면 초기화됩니다. 지도 타일처럼 네트워크가 필요한 기능은 HTTP 미리보기로 확인합니다.

저장소 루트에서 선택 사항인 정적 서버를 실행합니다. 설치·빌드 과정은 없습니다.

- FEED: `http://127.0.0.1:8742/current.html#/feed`

## 현재 ABOUT: 하나의 X 점군

후속 피드백에 따라 두 SVG 모션·이미지 창·건물 스터디를 모두 제거했습니다. ABOUT의 검은 영역을 화면 양 끝까지 넓히고 하나의 Canvas 2D 점군을 더 크게 표시합니다. 페이지 나머지는 기존 흰 배경입니다.

- 서로 다른 크기·비율·각도의 흰 X가 입체 표면을 이루고 계속 회전합니다. 데스크톱은 1,400개, 좁은 캔버스는 800개로 조정합니다.

## 프로젝트 날짜와 기간

시작 날짜와 종료 날짜를 각각 직접 입력하거나 달력에서 고릅니다. 종료 날짜를 비우면 단일 날짜입니다.

| 입력 | 저장·표시 |
|---|---|
| `920128`, `19920128`, `1992-01-28` | `1992.01.28` |
| `260112` | `2026.01.12` |
| `1992` | 연도만 |
| `199201`, `1992.01` | 연월만 |
| 시작 `2026.01`, 종료 `2026.10` | `2026.01 — 2026.10` |

6자리는 유효한 `YYMMDD`로 먼저 해석합니다. 2자리 연도는 00~49 → 2000~2049, 50~99 → 1950~1999입니다. 따라서 `200101`은 `2020.01.01`이며, 2001년 1월을 뜻한다면 `2001.01`로 입력합니다. 윤년·없는 날짜·역전 기간은 저장 전 검증합니다. 연도·연월 입력의 정밀도를 유지하며 임의의 ‘1일’을 표시하지 않습니다.

`year`·`month`는 시작 날짜에서 계속 계산해 기존 데이터·정렬과 호환합니다. `sort`는 기존처럼 연월 기준이며 같은 연월 안에서는 시작 일을 고려합니다. 종료 날짜로 기본 정렬하지 않습니다.

## 운영 DB에 필요한 추가 열

[PROJECT_FIELDS.sql](PROJECT_FIELDS.sql)은 `projects`에 다음 nullable 열만 추가합니다.

- `date_start text`: `YYYY`, `YYYY.MM`, `YYYY.MM.DD`를 구분해 저장.
- `date_end text`: 종료 날짜, 단일 날짜는 null.
- `location_point jsonb`: `{lat, lng}` 좌표, 위치명은 기존 `loc`에 저장.

기존 열·행·표·RLS·권한·Auth·Storage를 바꾸지 않습니다. text는 날짜의 연/월/일 정밀도와 기존 표시 형식을 유지하기 위해 사용합니다. [PostgreSQL ALTER TABLE 문서](https://www.postgresql.org/docs/current/sql-altertable.html)를 기준으로 `ADD COLUMN IF NOT EXISTS`를 사용했습니다.

개발 중 연결된 BYX 운영 DB의 열 목록을 읽기 전용으로 확인했을 때 위 세 열은 없었습니다. 마무리 문서 정리에서는 운영 DB를 다시 조회하거나 SQL을 실행하지 않았습니다. 추가 열이 없을 때 기존 연월·위치명 저장은 유지하고, 일 단위 날짜·기간·좌표 저장은 안내 후 중단해 데이터가 조용히 유실되지 않게 했습니다. 열이 없는 빈 표에서는 저장 시 서버 오류와 안내로 확인합니다.

## 지도 외부 요청

관리자가 지도 창을 열 때만 현재 보이는 영역의 OpenStreetMap 래스터 타일을 요청합니다. 별도 JS 라이브러리·API 키를 추가하지 않았습니다. 출처 표시와 기본 브라우저 캐시·Referer를 유지하며 미리 받기·오프라인 지도 다운로드·주소 자동 완성을 수행하지 않습니다. [OSM 타일 이용 정책](https://operations.osmfoundation.org/policies/tiles/)을 확인했습니다. `file://`에서는 타일을 요청하지 않고 HTTP 미리보기 안내와 직접 좌표 입력을 제공합니다.

## 구현 단계에서 수행한 검증

`tests/site-regression.cjs`는 운영 설정을 메모리에서 비운 격리 서버로 실행했습니다. 테스트 의존성은 기존 Playwright 설치를 사용했으며 제품에 추가하지 않았습니다.

구현 마무리 때의 회귀 기록은 **2026-11-03 17:53:45 KST**였고 문서만 정리한 단계에서는 재실행하지 않았습니다. 이후 사용자 GitHub 반영 요청에 따라 푸시 준비 중 다시 실행했으며, 최신 결과 시각은 **2026-11-03 18:08:41 KST**입니다(`results.json`의 UTC 시각: `2026-11-03T09:08:41.810Z`). 5개 화면 폭·10개 라우트가 통과했고 브라우저 실행 오류는 0건입니다.

- 2560·1920·1440·390·320px × 기존/새 10개 라우트 렌더·가로 넘침.
- 프로젝트 0·1개일 때 푸터 하단, 많은 프로젝트의 연속 배치 로딩.
- Instagram 주소, 상태 후보·임의 상태, 숫자 날짜·달력 연동·윤년·기간·같은 월의 일 정렬.
- 프로젝트 편집 → 지도 클릭 → 위치명 지정 → 날짜/기간/좌표 메모리 저장 → 공개 상세 표시.
- ABOUT 카드 크기·점군 회전/형태/분산·모션 감소, 통합 FEED에서 비밀글 제외.
- 점군의 화면 전체 폭·흰 제목·캡션 제거·4.8초 순환·확대된 호버와 실제 클릭 분산·복귀, FEED 최신 카드/아카이브 크기·모바일 2열·빈/단일 목록·안전한 링크.

- 추가 열이 없는 저장 payload에서 새 열 제외, 기존 year/month 보존.

미검증: 실제 지도 타일 응답·타일 오류/지원 환경 전체, 운영 로그인·실제 저장·SQL 실행, 실제 모바일/Safari/Firefox, 이미지 업로드·갤러리 전체 조작의 재검증, Vercel 대시보드. 지도 자동 테스트는 모의 타일로 수행해 실제 OSM 서버에 자동 요청을 보내지 않았습니다. 과거 검증을 이번 결과로 포함하지 않았습니다.

재실행은 Playwright와 Chrome이 이미 설치된 개발 환경에서만 필요합니다. 미리보기 실행에는 아래 도구가 필요하지 않습니다.

```powershell
$env:BYX_PLAYWRIGHT_MODULE = '기존 Playwright 패키지의 절대 경로'
$env:BYX_BROWSER = '설치된 Chrome 실행 파일의 절대 경로'
node tests/site-regression.cjs
```

다음 작업에서는 실제 27인치 2K 화면과 휴대전화에서 크기·스크롤 체감·모션 성능, Safari/Firefox와 유리 헤더 가독성을 확인합니다. 운영에서 날짜·기간·좌표를 저장하려면 추가 열의 적용 여부를 먼저 결정하고 별도 운영 검증을 수행해야 합니다. Wanted Sans의 실제 적용은 보류 상태이며 현재 SUIT를 유지합니다.

문서 마무리 당시에는 운영 SQL 적용·커밋·푸시·배포를 수행하지 않았고 MD만 변경했습니다. 이후 사용자의 커밋·푸시 지시 범위는 문서 상단의 후속 요청을 따릅니다. 운영 SQL·별도 운영 배포는 수행하지 않습니다. 기존 사용자 변경과 `.claude/`를 보존하고 개인 설정을 커밋에 포함하지 않습니다.
