# BYX 브랜드 구현 계획

작성일: 2026-10-25. 최종 정리일: 2026-11-03. 상태: 초기 개발 기준·계획 수립 완료 / 후속 사이트 개선 로컬 구현·데모 검증 완료 / 운영 미배포.

기준: [AGENTS.md](../AGENTS.md), [브랜드 기준](BYX_BRAND.md), [PROJECT.md](../PROJECT.md), [CLAUDE.md](../CLAUDE.md), [CHANGELOG.md](../CHANGELOG.md), [배포 가이드](../배포-가이드.md).

후속 단계 마무리(2026-11-03): 아래 문서화 단계의 범위·완료 체크는 당시 기록입니다. 이후 사용자 지시로 `index.html`의 푸터·순차 로딩·프로젝트 편집·WORKS 밀도/고정 TOP 버튼·ABOUT 점군·유리 헤더·FEED 카드 구성을 로컬 구현했습니다. Anton과 기존 구조를 유지합니다. 현재 결과·실행 방법·검증·운영 DB 적용 대기·미검증 항목은 [작업 정리](SITE_UPDATES_2026-11-03.md)를 따릅니다. 초기 계획 전체나 전체 브랜드 적용이 완료되었다는 뜻은 아니며 운영 배포는 수행하지 않았습니다.

## 1. 목표와 이번 범위

기존 기능과 배포 구조를 유지하면서 X 중심의 브랜드 시스템을 적용할 기준·순서·검증 방법을 정합니다. 요청된 세 문서는 저장소에 이미 있으므로 이번 변경은 해당 문서의 재검토·갱신으로 한정합니다. `index.html`, `vercel.json`, 기존 개발·운영 문서와 자산은 수정하지 않고 데이터베이스·인증·Storage·배포 설정도 변경하지 않습니다. 커밋·푸시·배포는 수행하지 않습니다.

이후 단계는 실행 완료 항목이 아닌 후속 작업 계획입니다. 미결 디자인을 확정 사양으로 취급하지 않으며 프레임워크·추가 빌드 도구·런타임 라이브러리를 도입하지 않습니다.

## 2. 소스 분석 기준선

- 2026-11-04 화면 정리 후속: 헤더 75% 축소·알약 메뉴, ABOUT 고정 챕터 탐색/영문 보조 문구 제거, `eXperience` 표기와 점군 여운을 반영했습니다. 실행 코드는 계속 단일 HTML이며 기존 설정·운영 가이드·사업자 푸터를 보존합니다. [후속 검증](ABOUT_STORY_2026-11-04.md#후속-화면-정리).

- 2026-11-04 ABOUT 후속: `viewAbout()`의 3개 챕터와 `bindAboutStory()`가 기존 X 점군 수명주기를 합성합니다. ABOUT 문구는 `settings.v`의 선택 필드로 추가하며 테이블·운영 값·서체·설정 객체·Vercel 설정은 바꾸지 않습니다. 사용자 제공 사업자 정보만 공통 푸터에 추가했습니다. [ABOUT 검증 기록](ABOUT_STORY_2026-11-04.md).

- 2026-11-04 후속 기준: 운영 `main`의 별도 브랜드 가이드(`/guidelines`, `/api/guidelines`, 가이드 전용 Wanted Sans와 추가 Vercel rewrite)가 존재해 현재 디자인 브랜치에 통합·보존했습니다. 본문 SUIT/영문 Anton은 유지합니다. 유리 헤더는 60% 흑백 전환형으로 갱신했으며, 운영 Storage INSERT 정책 누락은 별도 수정했습니다. 아래 수치·구조는 11-03 분석 당시 기록입니다. [최신 작업 기록](SITE_UPDATES_2026-11-04.md).

- 기준 브랜치: `design/byx-brand-identitycodex`. 검토 시작 커밋: `c0e684c` (`branding renewal`). 2026-11-03 로컬 작업 트리 기준이며 운영 사이트의 버전을 뜻하지 않습니다.
- `index.html` 2,728줄, 584,499바이트(재검토 시점). 폰트·파비콘·CSS·JS가 내장된 단일 실행 파일입니다. 기존 문서의 줄 수·용량 설명은 일부 오래되었습니다.
- 폰트는 Anton과 SUIT Variable, 외부 JS는 고정 버전 `supabase-js@2.112.3`입니다. CONTACT에는 Google Maps iframe 외부 로드가 추가될 수 있습니다.
- `parseHash()` → `render()` → 문자열 뷰 → `bindPage()` 흐름입니다. 전역 서체·레이아웃 변경은 공개 화면과 ADMIN에 함께 영향을 줄 수 있습니다.
- `DB`가 Supabase Auth·테이블·Storage와 데모 메모리 저장을 감쌉니다. `settings`와 추가 열에는 호환 처리가 있습니다.
- `window.BYX_CONFIG`의 `url`, `key`, `bucket`이 설정 지점입니다. 새 문서에 값은 복사하지 않습니다. 로컬에는 `.env`나 환경변수 주입 코드가 확인되지 않았지만 Vercel 대시보드의 환경변수 존재 여부는 미확인입니다.
- `vercel.json`은 `/admin`, `/admin/`을 `/index.html`로 rewrite합니다. 부팅 코드가 `/#/admin`으로 넘깁니다. 배포 문서는 GitHub → Vercel, Framework `Other`, 빌드·출력 경로 비움을 안내합니다. 실제 운영 브랜치·도메인·대시보드 설정은 미검증입니다.
- 이번 분석은 소스·문서 검토입니다. 기존 CHANGELOG의 테스트 결과는 과거 기록이며, 이번에 브라우저·운영 로그인·실제 저장을 재검증한 결과가 아닙니다.

탐색 지점: CSS `:root`, `#brand`, `.optical`, `.art`, `svgArt()`, `DB`, `spin()`, `parseHash()`, `viewProjects()`, `viewProjectDetail()`, `viewNews()`, `viewBlog()`, `viewPost()`, `viewAbout()`, `viewContact()`, `bindAdmin()`, `bindGalleries()`.

### 유지할 연결 구조

| 계층 | 현재 연결 | 후속 변경의 경계 |
|---|---|---|
| 설정·부팅 | `window.BYX_CONFIG` → `CFG` → `DB.init()` → `render()` | 설정 값·키·버킷·초기화 순서 유지 |
| 공개 화면 | `parseHash()` → 문자열 뷰 → `#app.innerHTML` → `bindPage()` | X를 추가해도 라우트·링크·이벤트 재연결 유지 |
| CMS | `projects` / `news` / `posts`, ABOUT·CONTACT용 `settings` | 열 이름·payload·본문 블록·기본값 유지 |
| 관리자 | `AD.draft` → 입력 갱신 → 저장, `AD.back` → `leaveEditor()` | 타이핑 중 전체 교체 금지, 미리보기·복귀 유지 |

배포는 이 계획의 자동 실행 단계가 아닙니다. 이번에는 하지 않습니다. 추후 배포 지시가 있을 때 기존 연결을 유지하고 검증된 변경만 반영합니다.

### 구현 범위를 정할 때

- 새 변수 이름·기하 수치·모션 시간은 현재 확정하지 않습니다. 선택 결과와 연결해 `:root`·CSS·inline SVG 안에서 관리할 후보를 정합니다.
- 디스플레이 서체가 미확정이어도 후속 지시에 따라 본문 또는 X 비교 작업은 독립적으로 진행할 수 있습니다. 전역 폰트 일괄 교체는 피합니다.
- Wanted Sans의 폰트 파일·버전·고지 자료를 검토하고 기존 내장 구조와 용량을 비교합니다. 폰트 제작 도구나 npm을 필수 개발 과정에 추가하지 않습니다.
- X 그래픽은 사진 URL·블록 배열·DB 열을 바꾸지 않는 표현 계층에서 우선 구현합니다. CMS에 X 설정 필드를 추가하는 계획은 없습니다.
- 실제 로고·파비콘·커서 변경은 이 계획에 포함된 확정 작업이 아닙니다. 특히 슬롯을 새로운 심벌로 교체하지 않습니다.
