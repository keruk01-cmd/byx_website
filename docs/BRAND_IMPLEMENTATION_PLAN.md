# BYX 브랜드 구현 계획

작성일: 2026-10-25. 상태: 문서화 단계 완료 / 화면 구현 미착수.

기준: [AGENTS.md](../AGENTS.md), [브랜드 기준](BYX_BRAND.md), [PROJECT.md](../PROJECT.md), [CLAUDE.md](../CLAUDE.md), [CHANGELOG.md](../CHANGELOG.md), [배포 가이드](../배포-가이드.md).

## 1. 목표와 이번 범위

기존 기능과 배포 구조를 유지하면서 X 중심의 브랜드 시스템을 적용할 기준·순서·검증 방법을 정합니다. 이번 변경은 세 문서 작성으로 한정합니다. `index.html`, `vercel.json`, 데이터베이스, 기존 문서와 자산은 수정하지 않고 커밋·푸시·배포도 수행하지 않습니다.

이후 단계는 실행 완료 항목이 아닌 후속 작업 계획입니다. 미결 디자인을 확정 사양으로 취급하지 않으며 프레임워크·추가 빌드 도구·런타임 라이브러리를 도입하지 않습니다.

## 2. 소스 분석 기준선

- `index.html` 2,728줄, 584,499바이트(작성 시점). 폰트·파비콘·CSS·JS가 내장된 단일 실행 파일입니다. 기존 문서의 줄 수·용량 설명은 일부 오래되었습니다.
- 폰트는 Anton과 SUIT Variable, 외부 JS는 고정 버전 `supabase-js@2.112.3`입니다. CONTACT에는 Google Maps iframe 외부 로드가 추가될 수 있습니다.
- `parseHash()` → `render()` → 문자열 뷰 → `bindPage()` 흐름입니다. 전역 서체·레이아웃 변경은 공개 화면과 ADMIN에 함께 영향을 줄 수 있습니다.
- `DB`가 Supabase Auth·테이블·Storage와 데모 메모리 저장을 감쌉니다. `settings`와 추가 열에는 호환 처리가 있습니다.
- `window.BYX_CONFIG`의 `url`, `key`, `bucket`이 설정 지점입니다. 새 문서에 값은 복사하지 않습니다. 로컬에는 `.env`나 환경변수 주입 코드가 확인되지 않았지만 Vercel 대시보드의 환경변수 존재 여부는 미확인입니다.
- `vercel.json`은 `/admin`, `/admin/`을 `/index.html`로 rewrite합니다. 부팅 코드가 `/#/admin`으로 넘깁니다. 배포 문서는 GitHub → Vercel, Framework `Other`, 빌드·출력 경로 비움을 안내합니다. 실제 운영 브랜치·도메인·대시보드 설정은 미검증입니다.
- 이번 분석은 소스·문서 검토입니다. 기존 CHANGELOG의 테스트 결과는 과거 기록이며, 이번에 브라우저·운영 로그인·실제 저장을 재검증한 결과가 아닙니다.

탐색 지점: CSS `:root`, `#brand`, `.optical`, `.art`, `svgArt()`, `DB`, `spin()`, `parseHash()`, `viewProjects()`, `viewProjectDetail()`, `viewNews()`, `viewBlog()`, `viewPost()`, `viewAbout()`, `viewContact()`, `bindAdmin()`, `bindGalleries()`.

## 4. 단계별 계획

| 단계 | 작업과 산출물 | 진입 조건 | 완료 기준 |
|---|---|---|---|
| 0. 기준 문서 | 루트 AGENTS와 브랜드·구현 계획 작성 | 현재 사용자 요청 | 세 문서만 추가, 보호 파일 불변 확인 |
| 1. 현행 기준 화면 | 기존 커밋 식별과 화면·동작 기록, 테스트 데이터 구분 | 후속 구현 착수 지시 | 전체 라우트와 1440/390/320px 기준, 데모·운영 미검증 목록 기록 |
| 2. 브랜드 비교안 | X 기본형/변형표, 이미지 프레임 비교, 디스플레이 시편·Wanted Sans 검토 | 브랜드 문서의 미결 ID 확인 | BYX 고유안, 사용 범위·모션·폰트 선택 결과 문서화 |
| 3. 서체·토큰 적용 | 먼저 본문, 이어 확정된 디스플레이 범위를 작은 변경으로 적용 | T-01/T-02 등 관련 선택 완료 | 줄바꿈·한글 굵기·관리 폼·로고 불변·폰트 실패 폴백 검증 |

배포는 이 계획의 자동 실행 단계가 아닙니다. 이번에는 하지 않습니다. 추후 배포 지시가 있을 때 기존 연결을 유지하고 검증된 변경만 반영합니다.

### 구현 범위를 정할 때

- 새 변수 이름·기하 수치·모션 시간은 현재 확정하지 않습니다. 선택 결과와 연결해 `:root`·CSS·inline SVG 안에서 관리할 후보를 정합니다.
- 디스플레이 서체가 미확정이어도 후속 지시에 따라 본문 또는 X 비교 작업은 독립적으로 진행할 수 있습니다. 전역 폰트 일괄 교체는 피합니다.
- Wanted Sans의 폰트 파일·버전·고지 자료를 검토하고 기존 내장 구조와 용량을 비교합니다. 폰트 제작 도구나 npm을 필수 개발 과정에 추가하지 않습니다.
- X 그래픽은 사진 URL·블록 배열·DB 열을 바꾸지 않는 표현 계층에서 우선 구현합니다. CMS에 X 설정 필드를 추가하는 계획은 없습니다.
- 실제 로고·파비콘·커서 변경은 이 계획에 포함된 확정 작업이 아닙니다. 특히 슬롯을 새로운 심벌로 교체하지 않습니다.

## 5. 주요 위험과 대응

| 위험 | 대응 및 확인 |
|---|---|
| 정방형 서체로 메뉴·슬롯 폭 증가 | 로고 영향 범위를 분리하고 긴 단어·한영 제목·최소 폭을 비교. 슬롯 보호를 우선 |
| X 마스크로 건축 사진·도면 정보 손실 | 외곽 프레임/여백부터 시험, 상세 전체 이미지 유지, 원본 파일 불변 |
| X와 슬롯의 동시 모션으로 주의 분산 | 모션 적용 위치·트리거를 제한하고 정적 대안 비교 |
| 전역 CSS가 ADMIN까지 영향 | 폼·툴바·미리보기·포커스를 공개 페이지와 함께 확인 |
| 폰트/그래픽으로 파일·렌더 비용 증가 | 같은 조건에서 전후 용량·로드·레이아웃 이동·스크롤 비교, 추가 라이브러리 금지 |
| 오래된 문서의 완료 기록 오인 | 실제 소스와 현재 검증 결과를 분리하고 대시보드 상태를 추정하지 않기 |

기존 인계 기록에는 실제 관리자 저장·추가 열 적용·실제 콘텐츠 입력 등의 미완료 항목이 있습니다. 운영 상태는 이번에 확인하지 않았습니다. 앞선 분석의 비밀글 RLS·Storage 쓰기 정책 확인 필요성도 별도 운영 검증 과제로 남깁니다. 화면에서 숨기는 처리만으로 서버의 비공개 보장을 단정하지 않습니다. 브랜드 작업에 묶어 SQL·인증·권한을 변경하지 않습니다.

## 6. 후속 구현의 회귀 검증

### 화면과 그래픽

- 데스크톱 1440px, 모바일 390px, 좁은 320px에서 헤더·메뉴·표·본문의 넘침과 줄바꿈을 비교합니다.
- 전 공개 라우트·직접 상세 진입·뒤로/앞으로 이동·`/admin`·`/admin/`을 확인합니다.
- 슬롯: 최초 회전, 페이지 이동 회전, 홈 클릭, 회전 중 연장, 긴 단어 맞춤, 고정 밑줄, 정상 착지, 숨은 탭 복귀, 모션 감소를 확인합니다. 보이는 탭에서 실제 움직임도 검증합니다.
- X 적용 전후에 사진·도면의 주요 정보와 클릭 영역을 비교합니다. 키보드 focus·터치·모션 감소·지원되지 않는 장식 효과에서도 탐색과 내용은 유지되어야 합니다.
- 글자 굵기·한영 혼용·숫자·링크·색 서식·폰트 로드 실패 폴백을 확인합니다. 콘솔 오류를 확인합니다.

### 기능과 CMS

- WORKS GRID/INDEX 전환, 6개 단위 추가, 연월·각 열 정렬과 상세 이동.
- NEWS 사진·외부 링크, BLOG 목록·상세·공개/비밀글의 기존 화면 판정.
- 블로그 텍스트↔블록 왕복, 서식·색·목록·정렬·이미지 묶음, 커버·갤러리 화살표/점/카운터/스와이프.
- ABOUT 구성원·이력·사진, CONTACT 이메일 복사와 폴백·지도/약도.
- ADMIN 로그인·로그아웃, 편집바 표시, 생성·수정·삭제·취소·저장 후 복귀, 타이핑 중 포커스·선택과 미리보기.
- 이미지 업로드·축소와 기존 원본 유지 예외, 데모 초기화, settings/추가 열 누락 호환.

데모 검증은 운영 설정을 바꾸지 않는 격리 사본과 임시 저장소로 수행합니다. 테스트 의존성을 제품에 추가하지 않습니다. 실제 CMS 쓰기는 허용된 시험 환경·시험 레코드에서 검증하며 기존 콘텐츠를 시험용으로 덮어쓰거나 삭제하지 않습니다. 운영 검증이 수행되지 않았다면 결과에 미검증으로 남깁니다.

### 변경·복구 범위

- `git diff`로 설정 객체·라우트·DB payload·`vercel.json` 변경 여부를 확인합니다. 환경변수와 원격 설정도 변경 대상에 포함하지 않습니다.
- 비교 기준 커밋과 바뀐 표현 영역을 기록합니다. 문제 발생 시 해당 브랜드 표현만 되돌릴 수 있게 변경을 나눕니다. 복구를 이유로 DB나 사용자 변경을 초기화하지 않습니다.
- 결과 보고는 실제 실행한 확인과 계획만 있는 확인을 구분합니다. 새 문서 작성만으로 기존 기능이 브라우저에서 모두 검증되었다고 하지 않습니다.
