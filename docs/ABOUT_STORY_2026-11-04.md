# ABOUT · 가능성을 만드는 시스템

2026-11-04. 사용자 후속 요청: 회사를 제품·서비스처럼 소개하는 감성적인 3개 챕터, 핵심 개념 Variable X × eXperience, 고객 경험과 건축·기술·데이터 역량. 이어서 공통 푸터 최하단의 사업자 정보 표시를 요청했습니다.

## 메시지와 화면

첫 화면은 `POSSIBILITIES. BY X.`와 “미지수는 가능성으로. 과정은 경험으로.”입니다. 기존 흑백·Anton/SUIT·슬롯 로고·1px 선을 유지하며, 큰 문구와 충분한 여백, 검정과 흰색 화면의 전환으로 소개 흐름을 구성합니다.

1. **가능성을 만드는 시스템**: 가장 중심인 챕터입니다. Variable X는 서로 다른 장소·사람·프로젝트 조건, eXperience는 그 안에서 만들어지는 경험입니다. 세 관점을 선택하면 설명과 X 점군 형상이 달라집니다. 자동 회전·형태 전환·호버/터치/키보드 반응을 유지합니다.
2. **과정까지 좋은 경험으로**: 대화와 발견 → 이해와 방향 → 설계와 대화 → 완성과 일상의 네 단계를 선택해 설명과 경로 드로잉을 탐색합니다. 고객의 경험을 바탕으로 설계하고, 함께 설계하는 과정도 경험으로 다룬다는 뜻입니다.
3. **건축가이자 개발자**: AI와 필요한 도구/일하는 방식의 직접 설계, 자체 법령 DB·CoreArc·민원·협력사 정보의 연결을 소개합니다. 데이터 소스를 선택해 어떤 판단과 서비스에 연결되는지 읽을 수 있습니다.

“다른 기업은 AI를 잘 쓰지 못한다”는 비교·단정 대신 BYX가 건축과 소프트웨어 개발을 함께 수행한다는 사용자 제공 역량에 집중했습니다. 실제 데이터·통계·새 사례·성과 수치를 만들지 않았습니다. 소개용 인터랙션이며 운영 DB나 CoreArc 계산 API를 새로 연결한 기능은 아닙니다.

참고한 페이지는 [ManualGraphics About](https://manualgraphics.com/about/)의 정체성·태도·서비스 연결 방식과 [Apple 제품 페이지](https://www.apple.com/kr/macbook-pro/proled-xdr-display/)의 챕터별 제품 설명 흐름입니다. 참고 페이지의 문구·이미지·로고·모션을 복제하지 않았습니다.

## 기존 기능과 편집

- `viewAbout()` → `bindPage()`의 문자열 렌더 흐름 안에서 `bindAboutStory()`를 연결합니다. 챕터 탐색, 선택 버튼과 내용은 전체 렌더 없이 갱신하며 라우트 이탈 시 관찰자와 점군 프레임을 정리합니다.
- 세 챕터 탐색은 네이티브 스크롤을 사용합니다. 버튼은 Enter/Space와 좌우 방향키/Home/End로 조작하고 선택 상태와 설명 변경을 보조기술에 전달합니다. 모션 감소에서는 정적인 상태와 즉시 전환을 제공합니다.
- ABOUT 제목·소개·마무리 9개 필드를 기존 `settings.v` JSON 안에서 선택적으로 저장합니다. 열 추가·운영 설정 쓰기는 없습니다. 과거 설정에 필드가 없거나 비어 있으면 현재 기본 문구를 표시합니다.
- 기존 `lede`, `studio`, `facts`, `records`, `people`은 보존합니다. Studio/Records는 아래의 펼침 영역, People은 기존 구성원 그리드로 표시하며 관리자에서 계속 편집합니다.
- 다른 라우트·통합 FEED·유리 헤더·업로드·브랜드 가이드·Vercel rewrite·`BYX_CONFIG`는 보존합니다. 실행 코드는 단일 HTML이며 라이브러리·폰트·빌드 단계는 추가하지 않았습니다.
