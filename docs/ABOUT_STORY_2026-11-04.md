# ABOUT · 가능성을 만드는 시스템

2026-11-04. 사용자 후속 요청: 회사를 제품·서비스처럼 소개하는 감성적인 3개 챕터, 핵심 개념 Variable X × eXperience, 고객 경험과 건축·기술·데이터 역량. 이어서 공통 푸터 최하단의 사업자 정보 표시를 요청했습니다.

## 메시지와 화면

첫 화면은 `POSSIBILITIES. BY X.`와 “미지수는 가능성으로. 과정은 경험으로.”입니다. 기존 흑백·Anton/SUIT·슬롯 로고·1px 선을 유지하며, 큰 문구와 충분한 여백, 검정과 흰색 화면의 전환으로 소개 흐름을 구성합니다.

1. **가능성을 만드는 시스템**: 가장 중심인 챕터입니다. Variable X는 서로 다른 장소·사람·프로젝트 조건, eXperience는 그 안에서 만들어지는 경험입니다. 세 관점을 선택하면 설명과 X 점군 형상이 달라집니다. 자동 회전·형태 전환·호버/터치/키보드 반응을 유지합니다.
2. **과정까지 좋은 경험으로**: 대화와 발견 → 이해와 방향 → 설계와 대화 → 완성과 일상의 네 단계를 선택해 설명과 경로 드로잉을 탐색합니다. 고객의 경험을 바탕으로 설계하고, 함께 설계하는 과정도 경험으로 다룬다는 뜻입니다.
3. **건축가이자 개발자**: AI와 필요한 도구/일하는 방식의 직접 설계, 자체 법령 DB·CoreArc·민원·협력사 정보의 연결을 소개합니다. 데이터 소스를 선택해 어떤 판단과 서비스에 연결되는지 읽을 수 있습니다.

“다른 기업은 AI를 잘 쓰지 못한다”는 비교·단정 대신 BYX가 건축과 소프트웨어 개발을 함께 수행한다는 사용자 제공 역량에 집중했습니다. 실제 데이터·통계·새 사례·성과 수치를 만들지 않았습니다. 소개용 인터랙션이며 운영 DB나 CoreArc 계산 API를 새로 연결한 기능은 아닙니다.

참고한 페이지는 [ManualGraphics About](https://manualgraphics.com/about/)의 정체성·태도·서비스 연결 방식과 [Apple 제품 페이지](https://www.apple.com/kr/macbook-pro/proled-xdr-display/)의 챕터별 제품 설명 흐름입니다. 참고 페이지의 문구·이미지·로고·모션을 복제하지 않았습니다.

## 후속 화면 정리

사용자 추가 요청으로 다음과 같이 갱신했습니다. 아래 초기 구현 기록 중 고정 챕터 탐색에 관한 내용은 이 후속 수정으로 대체합니다.

- 헤더 높이 `clamp(74px,10.4vw,108px)` → `clamp(55.5px,7.8vw,81px)`. 로고 서체·슬롯 폭도 75%로 조정하고 고정 밑줄·긴 단어 맞춤·홈 이동·광학 보정은 유지합니다.
- 데스크톱 메뉴는 옅은 알약 배경이 나타나는 호버와 채워진 알약 선택 상태를 사용합니다. 선택 시 0.32초 확대/페이드, 누름 시 약한 축소. 흰 유리에는 검정 알약/흰 글자, 검정 유리에는 흰 알약/검정 글자입니다. 모션 감소에서는 의사 요소의 애니메이션과 전환도 중지합니다.
- 헤더 아래 고정 01/02/03 바와 관련 이벤트·IntersectionObserver·여백 규칙을 삭제했습니다. 세 챕터는 본문 순서대로 읽으며 조건·설계 과정·데이터 소스 선택은 그대로 동작합니다.
- `eXperience X` → `eXperience`. `VARIABLE X MEETS EXPERIENCE.`, `DIFFERENT QUESTIONS. NEW POSSIBILITIES.`와 중복 영문 챕터 설명, 대형 `ARCHITECTS. ALSO DEVELOPERS.`, 구성원 보조 슬로건을 제거했습니다. 과정 드로잉과 단계 설명은 한글 중심으로 정리하고 핵심 공식은 `Variable X × eXperience → 해답`입니다.
- 점별로 입력 영향을 약 1.6초 기억하고, 포인터가 떠난 점에는 낮은 복귀력과 느린 감쇠를 적용합니다. 직접 입력 중의 반발 강도는 보존합니다. 이후 일반 복귀력으로 안정적으로 모입니다. 자동 형태 전환의 4.8초 간격, 모션 감소의 즉시 반응/복귀, 화면 밖 정지와 라우트 정리를 유지합니다.

후속 검증: [ABOUT 결과](../tests/artifacts/about-story-results.json)의 1440/390/320px에서 헤더 81/55.5/55.5px, 메뉴 선택과 호버·색 반전·0.32초 애니메이션, 긴 슬롯 단어 맞춤, 불필요 UI/문구 부재, 기존 CMS·이스케이프·사업자 정보·가로 넘침 통과. 실제 모션에서 점군 변위는 최대 456.55px, 해제 1초 후 325.85px, 6초 후 0.01px로 남는 영향과 복귀를 확인했습니다. 이는 특정 테스트의 점군 최대 변위이며 모든 입력의 고정 수치가 아닙니다.

[5개 폭·10개 라우트 회귀](../tests/artifacts/results.json)도 새 복귀 시간 기준을 통과했습니다. [헤더·업로드 검증](../tests/artifacts/header-upload-results.json)에서는 배경·사진·메뉴·투명도 감소·가이드와 기존 이미지 변환 경로의 보존을 재확인했습니다. 브라우저 실행 오류 0건이며 가이드 단위 테스트 4개를 통과했습니다. 실제 휴대전화·Safari/Firefox·운영 CMS 저장은 미검증입니다.

## 기존 기능과 편집

- `viewAbout()` → `bindPage()`의 문자열 렌더 흐름 안에서 `bindAboutStory()`를 연결합니다. 챕터 탐색, 선택 버튼과 내용은 전체 렌더 없이 갱신하며 라우트 이탈 시 관찰자와 점군 프레임을 정리합니다.
- 세 챕터는 네이티브 스크롤로 읽습니다. 조건/과정/데이터 버튼은 Enter/Space와 좌우 방향키/Home/End로 조작하고 선택 상태와 설명 변경을 보조기술에 전달합니다. 모션 감소에서는 정적인 상태와 즉시 전환을 제공합니다.
- ABOUT 제목·소개·마무리 9개 필드를 기존 `settings.v` JSON 안에서 선택적으로 저장합니다. 열 추가·운영 설정 쓰기는 없습니다. 과거 설정에 필드가 없거나 비어 있으면 현재 기본 문구를 표시합니다.
- 기존 `lede`, `studio`, `facts`, `records`, `people`은 보존합니다. Studio/Records는 아래의 펼침 영역, People은 기존 구성원 그리드로 표시하며 관리자에서 계속 편집합니다.
- 다른 라우트·통합 FEED·유리 헤더·업로드·브랜드 가이드·Vercel rewrite·`BYX_CONFIG`는 보존합니다. 실행 코드는 단일 HTML이며 라이브러리·폰트·빌드 단계는 추가하지 않았습니다.

## 후속 콘텐츠 아이디어

사용자가 공개할 수 있는 실제 프로젝트를 정하면, “처음의 조건 → 함께 내린 선택 → 달라진 공간과 경험”의 한 사례를 첫 챕터에 연결할 수 있습니다. 실제 도구 화면과 판단 근거를 갖춘 CoreArc 사례도 세 번째 챕터를 보강할 수 있습니다. 이번에는 미제공 사례나 성과를 임의로 게시하지 않았습니다.
